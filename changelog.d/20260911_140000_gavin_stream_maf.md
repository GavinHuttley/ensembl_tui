ENH

- The MAF parser now reads a file a chunk at a time, using
  `scinexus.io_util.iter_splitlines()`, instead of loading the whole file and
  splitting it into a list of lines. Parsing one 79 MB compressed alignment
  file drops from 1382 MB peak to 142 MB, and installing an alignment no
  longer holds a decompressed copy of each file in memory. Block ids and the
  sequences parsed out of them are unchanged.

  Two consequences to be aware of. The file is decoded as it is read, so a
  decoding error now surfaces partway through a file rather than before the
  first block. And the encoding is sniffed from the first 100 bytes rather
  than assumed to be utf-8, so a file whose header is ASCII but which holds
  non-ASCII bytes further in will fail where it previously did not. Ensembl's
  own MAF files are ASCII throughout.
